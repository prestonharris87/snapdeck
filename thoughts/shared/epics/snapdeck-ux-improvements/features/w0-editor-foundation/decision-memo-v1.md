# Decision memo — Annotation editor foundation (box model + lossless persistence + shared transformer)

## Summary

`w0-editor-foundation` lays the structural spine for the Konva annotation editor: a generic box
primitive, lossless model persistence, and a shared `Konva.Transformer` mechanism. What was
non-obvious about how the team got here: the plan started with four FE stories (fe-001 through
fe-004) and a sentinel DevOps story; the BOSS HYBRID test ruling mid-decomposition (conv 0016)
forced the extraction of all serialize/project/deserialize logic into a NEW fifth story
(`STORY-fe-005`, `editor-model.js`) and converted the DevOps sentinel into a real manifest
registration story (`STORY-do-001`). The resulting `fe-005 → do-001 → fe-003/fe-004` dependency
chain is the load-bearing ordering constraint for the entire feature. A secondary non-obvious
decision was to ship a generic `type:"box"` primitive (never projected to the upstream lossy
format) rather than migrating the existing point-anchored `text` item, which kept the frozen
byte projection truly frozen with no regression risk.

## Positions held during planning

### frontend-architect

- **Advocated for:** Generic `type:"box"` subtype as the concrete box the foundation ships
  — model-only, never projected, direct seed for w1/w2 downstream. Rationale: avoids box→text
  re-projection complexity and regression on existing text; `{x,y,width,height}` geometry is
  reused verbatim by both w1 (text-box-autofit) and w2 (rectangle-tool). (STORY-fe-001 §Decision)
- **Drove the pure-module architecture:** after the BOSS HYBRID ruling (conv 0016), created
  `STORY-fe-005` as a new fifth story extracting `serializeModel` / `projectAnnotations` /
  `deserializeModel` into a UMD-style, side-effect-free `editor-model.js` that is both
  browser-injectable and node-importable. Chose UMD over ESM because a classic content script
  cannot parse the `export` keyword. (STORY-fe-005, conv 0019)
- **Ratified `attachBoxTransformer` as frozen contract surface #3:** single shared `Konva.Transformer`
  with scale-bake-on-`transformend` (`node.scaleX(1); node.scaleY(1)`) — the mechanism w1 and w2
  will call rather than rolling their own. (STORY-fe-002 §Revisions, STORY-fe-002 §What it should look like)

## Tensions accepted as known risk

- **Cross-viewport rescaling on hydration:** geometry loads verbatim in the stored `meta.viewport`
  coordinate space; if the viewport changes between capture and re-open, geometry will be
  misaligned. The w0 round-trip test reloads at the same viewport to avoid this.
  Risk owner: frontend-architect. Cite: STORY-fe-004 §How we're doing it
  ("cross-viewport rescaling is out of scope; the w0 round-trip test reloads at the same viewport").

- **Shared `background.js` push-window merge hazard (three same-wave editors):**
  w0-keyboard-shortcuts, w0-per-target-reports, and w0-editor-foundation all edit
  `extension/background.js` in orthogonal line regions. "BOSS sequences the merge window at push
  time" — accepted as a process dependency, not a code safeguard.
  Risk owner: backend-architect (noted explicitly). Cite: STORY-be-001 §Cross-domain contract
  ("BOSS sequences the merge window at push time").

## Alternatives rejected

- **Migrating point-anchored `text` item to box geometry** — rejected because it would force a
  box→`{x,y,text}` re-projection and risk drifting the frozen text bytes on the upstream payload.
  Text styling/auto-fit/re-geometry is w1-text-box-autofit's job.
  Cite: STORY-fe-001 §Decision ("Keeps the frozen projection truly frozen").

- **One `Konva.Transformer` per tool** (text-box tool creates its own, rectangle tool creates its
  own) — rejected in favor of a single shared instance exposed as `attachBoxTransformer(node, item)`,
  which w1 and w2 attach to rather than duplicating. Avoids transformer count drift and guarantees
  "exactly one transformer at a time" invariant.
  Cite: feature.md §UX patterns ("One shared transformer instance, reused across box subtypes —
  not one transformer per tool"); STORY-fe-002 §What it should look like.

- **ESM `export` syntax for the pure module** — rejected because classic content scripts in MV3
  isolated worlds cannot parse ESM `export` keywords. UMD wrapper chosen instead
  (`if (module.exports) module.exports = api; else root.__snapdeckEditorModel = api`).
  Cite: STORY-fe-005 §What it should look like ("no ESM export keyword (a classic content script
  can't parse ESM)").

- **Refactoring `background.js` to export functions** (adding `module.exports`) — rejected due to
  whole-file strict-mode and scoping regression risk; listener-seam test pattern chosen instead
  (capture `addListener` callback at import time).
  Cite: STORY-be-001 §Unit tests ("Do NOT add export/import/type:module to background.js
  (whole-file strict-mode/scoping regression risk)").

- **Adding `model` to the `/report/save` upstream payload** — rejected explicitly; downstream
  report→defects consumer must see a byte-identical bytestream. `model` is local-only.
  Cite: feature.md §Out of scope; STORY-be-001 §What it should look like ("saveReport()
  whitelist ... stays exactly as-is").

## Next actions

Mirror of `feature.md` §Acceptance criteria (source of truth):

- [ ] The editor's internal `model` represents arrows AND at least one box-shaped annotation
      primitive carrying `{x, y, width, height}` geometry.
- [ ] On ✓ Done, the editor→background resolve payload carries the existing lossy `annotations`
      projection **unchanged** AND a new additive lossless `model` field
      `{ version: 1, items: [...] }`.
- [ ] The lossy `annotations` projection and the upstream `/report/save` payload are
      **byte-for-byte identical** to pre-feature output for the same set of annotations.
- [ ] `background.js` stores the lossless `model` on the per-screenshot record (`screenshots[].model`),
      and does **not** add `model` to the upstream `/report/save` payload.
- [ ] A **select mode** exists, distinct from draw/create: clicking a box in select mode attaches
      a single shared `Konva.Transformer` (`rotateEnabled: false`).
- [ ] Drag-resizing or moving a selected box writes the new `{x,y,width,height}` back to the
      `model` item and commits a `snapshot()`.
- [ ] The shared transformer move/resize is exposed as an internal `editor.js` helper
      (`attachBoxTransformer`) that w1 and w2 attach to.
- [ ] **Round-trip identity:** `model → persist → load → model` is identity.
- [ ] Existing arrow behavior is preserved with **no regression**.
- [ ] No new editor page/tab, no change to capture, no change to the localhost-only guard,
      no report-store re-keying.
